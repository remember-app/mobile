# Remember — мобильное приложение

Expo / React Native (TypeScript), iOS + Android. Единственный клиент продукта; общается только с
`api`. Общий пакет типов с `api` не заводится — нужные типы дублируются здесь (`src/api.ts`).

Сейчас здесь клиент аккаунтов (m-3): вход тремя способами, токен сессии в `expo-secure-store`
(Keychain на iOS, EncryptedSharedPreferences на Android), ник, профиль, выход — и гейт, который
решает, какие экраны вообще существуют. Поверх него — воспоминания: список своих на главной,
создание нового, само воспоминание одним экраном без вкладок (лента кадров, «Ролики» первым блоком
над ней) и его настройки отдельным экраном — люди, обложка, название, даты, — плюс выбор кадров на
телефоне. Что где стоит — см. ниже.

**Экраны сейчас в переходном состоянии.** Библиотека деталей собрана по новому макету «Афиша»
(`design/spec.md`), а расстановка на части экранов осталась от прежней — её переписывают задачи
вехи, по экрану на задачу. То есть внешность деталей уже новая, а компоновка ещё не везде; разбирая
такой экран, не сверяйтесь с ним как с образцом — сверяйтесь со спекой. Собраны заново и сверены с
макетом: главный экран и создание (`src/app/index.tsx`, `src/app/create.tsx`, TASK-143), пять
экранов входа (`login`, `login/email`, `login/code`, `consent`, `set-username`, TASK-160), окно
открытого кадра со своими листами (`src/memory/frame-viewer.tsx`, TASK-211), настройки
воспоминания с его правкой (`memory/[id]/settings`, `memory/[id]/edit`, TASK-209) и само
воспоминание (`src/app/memory/[id].tsx` с `src/memory/`, TASK-207). У всех них каркас — `Board`
кита, а не свой `View` с отступом под строку статуса; у самого воспоминания каркаса нет вовсе —
там лента во всю ширину, а шапка и подвал висят над ней.

Из трёх входов вживую работает только почта. Apple и Google подключены целиком, но им нужны ключи
на стороне `api` — без них он отвечает `501` — и **dev-билд**: в Expo Go нет ни entitlement на
Sign in with Apple, ни нашей URL-схемы. Кнопке Google нужен вдобавок
`EXPO_PUBLIC_GOOGLE_CLIENT_ID`.

Экран входа показывает только те входы, которыми в этой сборке можно пройти: кнопки Apple нет там,
где `AppleAuthentication.isAvailableAsync()` отвечает `false`, кнопки Google — там, где не задан
`EXPO_PUBLIC_GOOGLE_CLIENT_ID`. Почта стоит всегда, и все три кнопки одного размера: на этом экране
акцента нет вовсе — какой вход чей, приложению знать неоткуда. Отказ `501` от сервера
обрабатывается по-прежнему: сигнал на телефоне может устареть, и тогда отвечать приходится словами.

Вход по почте — шесть цифр из письма (`login/email` → `login/code`), а не ссылка: сервер перестал
её слать (TASK-138). Перед первым ником стоит соглашение (`consent`): `POST /me/username` без него
отвечает `403`, поэтому гейт ставит экран соглашения первым, а форма ника на этот отказ уводит
обратно к нему, а не печатает его.

## Требования

- Node 20+
- Expo Go на телефоне **или** iOS-симулятор / Android-эмулятор
- Запущенный `api` (соседний репозиторий) — без него не войти, а главный экран вместо списка
  покажет ошибку и кнопку «Try again»

## Запуск

```sh
npm install
EXPO_PUBLIC_API_URL=http://localhost:3000 npx expo start
```

Дальше — `i` (iOS-симулятор), `a` (Android-эмулятор) или QR-код в Expo Go.

Чтобы не писать переменную каждый раз, положите её в `.env` (файл в `.gitignore`):

```sh
EXPO_PUBLIC_API_URL=http://localhost:3000
```

### `EXPO_PUBLIC_API_URL`

Базовый URL API. Без неё берётся `http://localhost:3000`.

`localhost` работает только на симуляторе/эмуляторе. **С телефона через Expo Go** подставьте
IP машины в локальной сети, например `EXPO_PUBLIC_API_URL=http://192.168.1.10:3000`.

Переменная подставляется в бандл на сборке — после её изменения перезапустите `expo start`.
По той же причине в `EXPO_PUBLIC_*` не кладутся секреты: содержимое уезжает в собранное приложение.

### Код входа по email в разработке

Когда на API явно включён `EMAIL_LOGIN_DEV_BYPASS` (значение `1` или `true`), адрес — на домене
`test.test`, а сам API не в проде, `POST /auth/email/start` отдаёт сам код прямо в ответе вместо
письма. Экран почты передаёт его дальше, в шесть ячеек, и они открываются заполненными под плашкой
«вход для разработки»: руками делать нечего — адрес, «Отправить код», «Подтвердить».

Нужны все три условия сразу. Ключи почты (`RESEND_API_KEY`, `MAIL_FROM`) на обход больше не
влияют: с любым другим адресом уходит настоящее письмо, а без ключей приходит 503.

В лог код не пишется, это ключ от аккаунта. Если он нужен отдельно — возьмите его из ответа:

```sh
curl -s localhost:3000/auth/email/start \
  -H 'content-type: application/json' -d '{"email":"you@test.test"}'
```

Схема `remember://` осталась только у приглашений (`remember://invite?token=…`) и работает лишь в
dev-билде: в Expo Go она принадлежит не нам, и `xcrun simctl openurl booted "remember://…"` падает
с `LSApplicationWorkspaceErrorDomain 115`. В Expo Go тот же экран открывается через схему Expo
(`exp://127.0.0.1:8081/--/invite?token=…`).

## Пуши

Код целиком в `src/push.ts` (хук `usePush()` в корневом навигаторе): после входа спрашивается
разрешение, токен уходит в `POST /me/push-tokens`, тап по пушу «вас позвали» открывает
`/memory/[id]/upload` того воспоминания. Пуш «ролик готов» несёт, кроме `montageId`, ещё и
`memoryId` — по нему открывается само воспоминание, где ролики стоят первым блоком ленты, новый
среди них: досылать туда нечего.
Не получилось — в логе Metro строка
`push registration skipped: …` (нет `projectId`, отказ в разрешении, симулятор); экрана про это
нет и не будет: пуш — не единственный способ узнать о приглашении.

**В Expo Go удалённых пушей нет** (с SDK 53), нужен dev-билд — поэтому в зависимостях
`expo-dev-client`, а в `eas.json` профиль `development`.

Чтобы это заработало вживую, нужен Expo-аккаунт — **этого шага здесь нет, и в коде ничего не
зашито**:

1. `npx eas init` в этой папке — он и запишет `expo.extra.eas.projectId` (и `owner`) в `app.json`.
   Именно это поле читает `getExpoPushTokenAsync`; без него в логе `No "projectId" found`.
2. `ios.bundleIdentifier` и `android.package` в `app.json` — их спросит первая `eas build` и
   запишет сама.
3. `npx eas build --profile development -p ios` (или `android`), поставить сборку на телефон,
   `npx expo start --dev-client`. Переменные (`EXPO_PUBLIC_API_URL`) dev-билд берёт с дев-сервера,
   то есть из локального `.env`, а не из сборки.
4. Ключи APNs / FCM — `npx eas credentials`.

Плагин `expo-notifications` ставит `aps-environment: development`; для TestFlight и прода ему
понадобится `mode: 'production'`.

## Оболочка и токены

Дизайн-правда продукта — `design/spec.md` в корневом репозитории (макет «Афиша»: ночь основная,
день — подстановкой), её единственный перенос сюда — `src/theme.ts`: цвета, ритм, радиусы по роли,
высоты, вертикальные привязки доски, длительности и шкала типографики, имена и значения один в один
со спекой. Свои цвета и отступы экраны не заводят — берут отсюда.

- Шрифты — **Unbounded** 600/700 на заголовки и **Onest** 400…700 на всё остальное
  (`@expo-google-fonts/unbounded`, `@expo-google-fonts/onest`), оба с кириллицей. Каждое начертание
  — своё имя семейства (`Unbounded_700Bold`), а не семейство плюс `fontWeight`: одноначертательному
  загруженному шрифту Android иначе синтезирует вес вместо того, чтобы взять готовый. Шесть
  начертаний грузятся в `_layout.tsx` и держат сплэш вместе с проверкой сессии. Что файлы
  действительно несут кириллицу, проверяет `src/tokens.test.ts` — читает cmap самого ttf, а не
  метаданные пакета.
- Значки — **Lucide** (`lucide-react-native`), один набор на весь продукт; обводка не одна на всех,
  а тем толще, чем мельче знак (`strokeFor` в `src/kit/icon.tsx`, 1.5–2.1). Он тянет за собой
  нативный `react-native-svg`: в Expo Go он есть, а **старый dev-билд надо пересобрать**.
- Градиенты — родные, `experimental_backgroundImage` со строкой CSS прямо из спеки (подвал донного
  слоя, затемнение обложки). Отдельной библиотеки под это нет; `experimental_` только в имени —
  RN 0.86 разбирает строку в JS и рисует её нативно.
- Кадры рисует **`expo-image`** (внутри `src/kit/tile.tsx`, наружу не торчит): родной `Image` не
  умеет `ph://…` — ссылку, которой iOS называет снимок в медиатеке, — и падает на ней красным
  экраном «No suitable image URL loader». `expo-image` спрашивает Photos напрямую, для видео
  отдаёт постер, и отдаёт уже уменьшенным под плитку. Модуль нативный: **старый dev-билд надо
  пересобрать**. Его манифест доливает в андроидную сборку `ACCESS_NETWORK_STATE` — разрешение
  обычного уровня, без диалога, но в списке на Play оно появится. Проявляется кадр **его же**
  `transition`, а не `Animated` поверх: нативный драйвер пишет прямо во вью, к которому привязан, а
  здесь это чужой класс вокруг нативного — значение доезжало до единицы в JS, картинка оставалась
  на нуле и появлялась только от постороннего перерендера. Плитки на экране выбора из-за этого были
  пустыми, пока по ним не ткнёшь.
- Свой трек для ролика выбирается системным выбором файлов — **`expo-document-picker`**
  (`audio/*`, только экран заказа). Модуль нативный и разрешений не просит, но **старый dev-билд
  надо пересобрать**.
- Музыку на том же шаге проигрывает **`expo-audio`** (`createAudioPlayer`, только экран заказа).
  Модуль нативный — **старый dev-билд надо пересобрать**. Его плагин в `app.json` стоит с
  выключенным микрофоном и фоновым воспроизведением (`microphonePermission: false`,
  `recordAudioAndroid: false`, `enableBackgroundPlayback: false`): приложение ничего не записывает и
  за пределами экрана заказа не звучит, а по умолчанию плагин просит `RECORD_AUDIO` и режим `audio`
  в фоне — и то и другое пришлось бы объяснять в сторах. Телефон живёт на беззвучном, поэтому перед
  каждым проигрыванием вызывается `setAudioModeAsync({ playsInSilentMode: true })` — без него iOS
  при выключенном звонке молчит.
- Родного хедера нет нигде (`headerShown: false`), фон навигатора — `ink` через `ThemeProvider`,
  так что шапку экран рисует сам.
- Приложение идёт за темой телефона, поэтому `userInterfaceStyle: "automatic"` в `app.json`: при
  `"dark"` система вообще не сказала бы, что телефон в светлом режиме, и светлая тема не включилась
  бы никогда. Настройка нативная — **ещё одна причина пересобрать dev-билд**.
- Продукт вертикальный, но нативного замка на это больше нет: в `app.json` стоит
  `orientation: "default"`, а портрет держит `src/orientation.ts` — `lockPortrait()` из
  `_layout.tsx` при запуске и снятие замка на время двух просмотров во весь экран, кадра и ролика
  (`useTurnsWithPhone` — окно кадра `src/memory/frame-viewer.tsx` и плеер ролика `films.tsx`). Окно кадра
  живёт ровно столько, сколько открыт кадр, поэтому флаг там простой `true`. Стоявший там `"portrait"` компилировался
  в Info.plist и андроидный манифест и был выше любого JS: `supportedOrientations` у обоих Modal
  не делал ничего, и открытый кадр не поворачивался вместе с телефоном (TASK-124). Замок ставит
  нативный `expo-screen-orientation`, и сама смена в `app.json` тоже нативная — **старый dev-билд
  надо пересобрать**.

### Тема — светлая и тёмная

Тем ровно две (`backlog/docs/doc-9`), и различает их только цвет: ритм, отступы, радиусы, шрифты и
длительности общие и о теме не знают. В `src/theme.ts` лежат оба набора: ночь нарисована в макете
целиком, день собран подстановкой по правилам раздела 2 спеки. У дня три места, где это не
подстановка, а другое решение, — карточку поднимает тень, а не обводка; затемнение поверх
фотографии остаётся тёмным; тень главной кнопки мягче. Каждая читаемая пара обоих наборов проверена
на контраст в `src/tokens.test.ts`, потому что на светлом `muted` идёт впритык (4.65 : 1).

- **Какая тема сейчас** — `src/theme.ts`: берётся от телефона (`Appearance` из React Native,
  нативного модуля для этого не нужно), меняется вместе с ним на ходу. `setTheme('dark' | 'light')`
  переопределяет систему, выбор лежит в `expo-secure-store` и переживает перезапуск. Устроено ровно
  как язык — модульная переменная и `useSyncExternalStore`, а не контекст.
- **Компонент рисует по актуальной теме**: свои стили он получает не импортом набора, а хуком —
  `const useStyles = themed(({ color }) => StyleSheet.create({ … }))`, дальше `useStyles()` в теле.
  Каждая тема собирается один раз и запоминается. Цвет, который нужен не в стиле, а в пропсе, —
  `useTheme()`.
- Кадры и медиа не перекрашиваются ни в одной теме: всё, что лежит **на фотографии**, а не на
  интерфейсе, собрано отдельно в `photo` — затемнение обложки, подложка метки, стекло просмотрщика,
  белый текст поверх. Оно одинаково в обеих темах.

### Библиотека деталей

`src/kit/` — детали раздела 7 спеки на React Native: каркас экрана (доска, шапка экрана в пяти
видах, стеклянная шапка ленты, мастер, просмотрщик, донный слой, лист, стеклянное меню действий),
кнопки (восемь видов и круглая на шесть диаметров), ввод (поле на семь видов, ячейки кода, длинный
текст, календарь, ползунок длины, палитра цветов, карточка-выбор, переключатель, сегменты, чип),
значки и метки, люди (аватар, стопка, пилюля «смотрят сейчас», строки участника и контакта),
карточки и строки, кадры (плитка, щель дня, стержень дат, плёнка, мозаика), поверхность монтажа
(шаблон, афиша итога, сводка заказа, карточка «Сейчас», плашка мысли, журнал режиссёра), лейблы,
пустое состояние и ожидание, мелочи (разделитель, точка меты, живая точка, шкала шагов, полоса
прогресса, дорожка видео, волна трека, стопка кадров, скрытая подпись). Единственное место,
откуда экраны берут внешний вид; импорт — из корня папки:

```tsx
import { AppBar, Button, CardMemory, Text } from '@/kit';
```

Значения берутся из `theme.ts`; своих цветов компоненты не заводят и жёстко тёмными не бывают.

Четыре вещи, о которые спотыкается тот, кто их подключает:

- **Ни одного зашитого слова.** Всё видимое приходит пропсом: библиотека — это внешность, слова у
  экранов. Склонения («1 ролик» / «2 ролика») тоже приходят готовыми.
- **Текст — только `Text` из кита.** В CSS цвет наследуется от `body`, в RN — ни от чего, поэтому
  родной `Text` с одним лишь `type.body` даёт чёрное по угольному. Роль просите словом:
  `<Text role="title">`, цвет — `tone`.
- **Движение гаснет по системной настройке.** Вращение, проявление кадра, подъём листа, сдвиг
  нажатия и полоса отправки слушают «уменьшить движение»; она спрашивается один раз на всё
  приложение в `src/kit/interaction.ts`. Оттуда же `hitSlop()` — им добирают до 44×44 всё, что
  нарисовано меньше (круглые 36 и 32), и `useFocusRing()` — кольцо фокуса, обязательное на каждом
  нажимаемом элементе.
- **Состояния — пропсом, а не второй деталью.** Кнопка не нажимается (`disabled`), ждёт сервер
  (`busy` плюс `busyLabel` — то же действие в продолженном времени), поле проверено или ошиблось
  (`state`), кадр выбран на отправку или взят домой (`pick`, и цвет говорит направление).
- **Сетка кадров — две, и плитка знает, в какой стоит.** Лента воспоминания идёт во всю ширину,
  щель `FEED_GAP` (2), без скругления (`<Tile lane="feed">`); мастер и очередь — в полях 16, щель
  `GRID_GAP` (3), радиус 4 (по умолчанию). Одна деталь, две раскладки: ширину колонки экран считает
  из своей щели.
- **Капсула стеклянной шапки — кнопка, только если есть куда вести.** Дали `onCapsule` — она
  кнопка и носит `chevron-down` (лента воспоминания, режим выбора); не дали — плашка-заголовок без
  шеврона (`Upload`). Мёртвая кнопка, которая объявляет себя кнопкой и не отвечает на нажатие, хуже
  той, что ею не притворялась.
- **У строки один правый знак.** В строке участника это либо значок вклада, либо своя кнопка 44,
  либо крестик режима правки состава — они заменяют друг друга в слоте `status`, а не встают рядом.

Два стекла, а не одно (спека 7.2): `tone="glass"` у круглой кнопки — шапка над лентой (`ink` 62 %
под размытием, со своей обводкой), `tone="viewer"` — стекло окна кадра. Перепутать их видно только
на фотографии, поэтому они названы по месту, а не по цвету.

Календарь (`src/kit/calendar.tsx`) — своя деталь, а не системный выбор даты: диапазон ставится одним
жестом, первый тап — день, второй — конец. Слов он не знает — имя месяца, буквы недели и подпись
каждого дня приходят пропсами, а неделя начинается с понедельника. Сами слова пишет `src/dates.ts`
(`formatMonth`, `weekdayLetters`) на языке, которым говорит приложение, а не телефон. Прежнего
поля-кнопки даты (`FieldShell` + системный `DateTimePicker`) больше нет — ни на экране, ни в ките,
ни в зависимостях. Вокруг календаря стоит блок «Когда это было»: строка диапазона, четыре быстрых
чипа, сам календарь и подпись. По спеке (10.8.3) он один и тот же на создании и на правке
воспоминания; `src/memory/when.tsx` — та его копия, которую рисует правка, `src/app/create.tsx`
пока держит свою. Сходятся они на общих помощниках дат и на словах `s.create.*`; меняете один —
меняйте оба, пока `Create` не переведут на `EventWhen`.

Своего тумблера у библиотеки нет — на выбор из значений отвечает `Segment`. Там, где вещь просто
включена или выключена, стоит платформенный `Switch` в цветах темы, и стоит он один раз: `Toggle`
(`src/kit/toggle.tsx`), у которого нажимается вся строка вместе с подписью. Один из его четырёх
цветовых пропсов (`activeThumbColor`, см. `src/switch.d.ts`) — из тех, чьё отсутствие никто не
замечает.

Лист снизу — это `Sheet` (`src/kit/sheet.tsx`): подложка, ручка 40×4, подъём, закрытие по тапу вне,
заголовок, тело (по надобности со скроллом) и неподвижный блок кнопок внизу. Пять видов листа из
спеки — это пять разных `footer`, а не пять флагов. На нём стоит `ConfirmSheet`, которым
спрашивается необратимое вместо системного `Alert.alert`: он называет цену цифрой до нажатия.

#### Истории

Отдельного Storybook нет и не будет (в браузере продукт не проверяется, см. «Чего здесь нет»).
История каждого вида и состояния — это тест рядом с деталью: `src/kit/*.test.tsx` рендерит её через
`react-native-web` и читает разметку. `src/kit/story.tsx` — вся оснастка: `story()` рисует одно
состояние, `allDifferent()` требует, чтобы перечисленные состояния отличались друг от друга (деталь,
неотличимая от соседней, — это не состояние). Нативные модули подменены один раз на весь прогон в
`vitest.setup.ts`, а не в каждом файле.

Той же оснасткой проверяется поверхность экрана, которой нечего держать, кроме переданного, —
сейчас это лист «Сведения о кадре» (`src/memory/frames-sheets.test.tsx`): его состояния (читаем,
не прочли, весь целиком) и то, что в светлой теме он выглядит иначе, чем в тёмной, — обе рисуются
через `<ThemePin>`, так что проверка на две темы не требует переключать тему приложения. Экраны
целиком так не рендерятся: у них роутер, запросы и своё состояние, и про них тесты читают исходник
(`src/*-screens.test.ts`).

Что видно в такой разметке, а что нет: стиль, собранный на рендере (тернарник, размер из пропса),
пишется в `style="…"` с цветами; стиль из `StyleSheet.create` — а это и всё, что возвращает
`themed()`, — сворачивается в класс-хеш. Поэтому цвет с двумя ответами читается прямо только там,
где он собран на рендере; форма и цвет из готового листа — сравнением одного состояния с другим.
Состояние доступности (`accessibilityState`) в статическую разметку `react-native-web` не попадает
вовсе: роль и подпись проверяются, «отмечено» — сравнением.

Шесть проверок шрифтов на кириллицу (`src/tokens.test.ts`) читают ttf по пути относительно текущей
папки, поэтому **в git-worktree они падают**: `node_modules` там свой и пустой. В обычной рабочей
копии они зелёные.

## Язык

Языка два — русский и английский, третьего не будет (`backlog/docs/doc-8`). Оба набора написаны
руками: английский не перевод русского, русский не перевод английского.

- **Слова** — `src/strings.ts`: один ключ, два набора. Форму задаёт `en`, `ru` обязан её заполнить,
  поэтому ключ с одним набором роняет `npm run typecheck`, а не показывает английское слово посреди
  русского экрана. Русские числительные считаются в трёх формах (`1 кадр`, `2 кадра`, `5 кадров`)
  своей функцией: `Intl.PluralRules` есть в Hermes не везде.
- **Язык** — `src/language.ts`: берётся от телефона (`expo-localization`), незнакомый язык телефона
  даёт английский. Переключается `setLanguage('ru' | 'en')`, выбор лежит в `expo-secure-store`
  (не секрет — просто хранилище, которое в приложении уже есть) и переживает перезапуск.
  Значение одно на всё приложение, поэтому это модульная переменная, а не контекст: `currentLanguage()`
  спрашивают из любой функции, компоненты берут `useLanguage()` / `useStrings()` и сами
  перерисовываются на переключении. Никакого i18n-фреймворка под этим нет — словарь и резолвер, как
  `theme.ts` для дизайна.
- **Даты** идут по языку приложения, а не по системной локали телефона: название месяца в
  `src/dates.ts` спрашивается у `currentLanguage()`. Раньше там стоял `undefined`, а это для
  форматтера значит «локаль устройства» — из-за него на телефоне с русской локалью посреди
  английских подписей стояло русское число.

`expo-localization` — нативный модуль: в Expo Go он есть, **старый dev-билд надо пересобрать**.
Поэтому же любой тест, который тянет `@/dates`, `@/language`, `@/theme` или любую деталь
библиотеки, подменяет `expo-localization` и `expo-secure-store` — в node их импорт падает на
`__DEV__`. Подмена общая и лежит в `vitest.setup.ts`, отдельно в файле теста её писать не нужно.

Экраны словарь ещё не читают (это отдельная задача вехи m-13), в `strings.ts` пока то, что
приложение говорит вне экранов: ошибки, состояния и слова, которые повторяются везде.

## Экраны

Навигация — `expo-router` (файловая маршрутизация, `src/app/`), корневой layout — `Stack` с гейтом.

Само воспоминание — **один экран без вкладок** (спека, раздел 8, `MemoryFrames`): лента кадров идёт
во всю ширину и высоту, блок «Ролики» стоит первым на ней, а стеклянная шапка и донный слой висят
поверх. До TASK-207 это был экран с лицами под переключателем (TASK-101), а до того — три маршрута;
ни переключателя, ни `?face=` больше нет, и любая дорога внутрь ведёт просто на `/memory/[id]`.
Параметр у экрана остался ровно один — `montage`: он поднимает плеер этого ролика и тут же
стирается, и так строка «В роликах» в сведениях о кадре открывает уже существующий плеер.

Всё в `src/app/` — маршрут, поэтому куски экрана лежат рядом, в `src/memory/`: лента `frames.tsx`,
блок роликов `films.tsx`, стеклянная шапка и заголовок блока `head.tsx`, окно открытого кадра
`frame-viewer.tsx` и листы кадров `frames-sheets.tsx` (фильтр, сортировка и лист самого кадра).
Там же куски, которые принадлежат не одному экрану: лист приглашения `invite-sheet.tsx`, обложка
`cover.tsx` (слот 68 и лист выбора кадра) и блок «Когда это было» `when.tsx` — строка диапазона,
быстрые чипы и календарь, один и тот же на правке воспоминания и (по спеке 10.8.3) на создании.
Маршрут (`src/app/memory/[id].tsx`) держит только само воспоминание — имя, даты, роль, сколько
человек, — читая его один раз, а свой список каждый блок читает сам.

Пять экранов входа (спека, «Онбординг») держат одну общую шапку — `src/onboarding-head.tsx`: стопка
кадров, «Remember», обещание продукта. Она прибита к верху доски, а не отцентрована по остатку, и
потому не съезжает, когда низ экрана меняется с трёх кнопок на поле, потом на шесть ячеек. У
`consent` та же шапка в сжатом виде. Три картинки под стопкой — заглушки макета
(`assets/images/onboarding/`), настоящих кадров до входа взять негде.

- **`login` — Sign in** (`src/app/login.tsx`) — три двери одного размера: Apple, Google, почта;
  недоступный провайдер не рисуется вовсе, а не стоит выключенным.
- **`login/email` — Sign in by email** (`src/app/login/email.tsx`) — адрес и «Отправить код»;
  `POST /auth/email/start`. «Назад» плавает над шапкой, чтобы её не сдвинуть.
- **`login/code` — Code from the letter** (`src/app/login/code.tsx`) — шесть ячеек, строка «Отправили
  на …» с тихой «Ещё раз» и «Подтвердить» (`POST /auth/email/verify` адресом и кодом). Неподошедший
  код — `401` на любую причину, поэтому ячейки краснеют, чистятся и отвечают одной строкой.
- **`consent` — Agreement** (`src/app/consent.tsx`) — соглашение (doc-04, decision-9): три строки, из
  них выделена та, что про распознавание лиц, полный текст листом снизу (текст в `strings.ts`,
  ничего не скачивается), «Принимаю» → `POST /me/consent`. Кнопки отказа нет: отказ — это уход с
  экрана, и подпись под кнопкой говорит об этом прямо.
- **`set-username` — Pick a username** (`src/app/set-username.tsx`) — ник; форма общая
  (`src/username-form.tsx`). `403` «consent required» — не ошибка про имя, а возврат на `consent`.
- **`index` — Remember** (`src/app/index.tsx`) — главный экран: список воспоминаний, где аккаунт
  организатор или участник (`GET /memories`). В шапке один значок, и это «Аккаунт»; свежее
  воспоминание ведёт список крупной карточкой, но только пока ему есть что нести — пустое берёт
  обычную карточку с пунктирной плёнкой. Выбранная организатором обложка (`cover_thumbnail_url`)
  — такая же фотография: она рисуется во всю крупную карточку вместо мозаики, в обычной встаёт
  первой в полосе, и её одной хватает, чтобы карточка была крупной. Не выбрал обложку — карточка
  ровно такая, какой была. Полоса «сколько уже скинули кадры» считана самим списком
  (`member_count` / `contributed_member_count`), запроса на карточку нет. Перезапрашивается на
  каждый фокус, поэтому возврат с `create` показывает новое воспоминание сам. Карточка открывает
  воспоминание на «Кадрах». Связь — полоса в верху тела, а не замена списку: сорвавшийся перезапрос
  оставляет список на месте и вешает над ним баннер с крестиком, вернувшаяся связь показывает
  `spark`-баннер, который уходит сам через `duration.hold`. Своей библиотеки состояний связи нет:
  всё это — три ответа одного `listMemories`.
- **`create` — New memory** (`src/app/create.tsx`) — название и «когда это было»: календарь кита
  прямо в форме, первый тап — день, второй — конец диапазона, третий начинает заново; тап раньше
  начала считается поправкой первого. Над ним строка выбранного («12–14 сентября · 3 дня»; один
  день — без длины) и четыре быстрых дня (`Сегодня · Вчера · Выходные · Неделя`), под ним — одна
  подпись. Тумблера «больше дня» и системного выбора даты больше нет. Показанный месяц — своё
  состояние, поэтому листание стрелками не трогает выбранное, а завтрашний день не выбирается
  вовсе (`max`). Уходит в `POST /memories` началом и концом **local** суток — `toISOString()`
  даёт RFC 3339 со смещением, которого требует `api`; один день конца не шлёт вовсе.
- **`memory/[id]` — Memory** (`src/app/memory/[id].tsx`) — само воспоминание, один экран без
  вкладок. Сверху стеклянная шапка (`MemoryHead` в `src/memory/head.tsx` на `GlassBar` кита): слева
  «назад» (без стека — `replace` на список), по центру капсула с именем и «даты · N человек», справа
  круглая «Выбрать». Капсула ведёт в настройки воспоминания (`memory/[id]/settings`), и шевроном под
  именем говорит, что ведёт; в режиме выбора шеврона нет — там та же капсула берёт все кадры. Снизу
  донный слой на 190 с тремя кнопками. Ни шапка, ни подвал не занимают места в ленте: оба висят над
  ней абсолютом, каждый со своим градиентом.
  - **Кадры** (`src/memory/frames.tsx`) — что сложили участники (`GET /memories/:id/media`): сетка
    деривативов по три в ряд **во всю ширину экрана**, щель `FEED_GAP` (2), без полей и без
    скруглений (`<Tile lane="feed">`) — её видит любой участник, включая `viewer`.
    Сетка разрезана на группы (`groupFrames` в `src/frames.ts`): по дням съёмки (свежий день
    сверху), по тем, кто принёс, или по типу — в строке группы стоит число кадров в ней, а в режиме
    выбора «Выбрать все N» по этой же группе. Что показать (кто принёс, тип, день) и в каком
    порядке — два листа снизу, `src/memory/frames-sheets.tsx`: фильтр остаётся черновиком, пока его
    не применили кнопкой с числом («Показать 486 кадров»), сортировка применяется сразу. Обе круглые
    кнопки подвала носят искру, когда их настройка ушла от умолчания (`filtering`, `arranged`).
    Оригиналы отсюда не тянутся вообще. Медиа, которому воркер ещё (или уже никогда) не сделал
    превью, — плитка с подписью вместо картинки. Тап открывает кадр во весь экран
    (`src/memory/frame-viewer.tsx`, экраны `Viewer` и `ViewerVideo` спеки): всё управление — три
    стекла сверху, «Закрыть» · капсула «когда» над «время · автор» · «⋯», а снизу только лента
    миниатюр для листания (`Filmstrip` кита). Ряда круглых кнопок под лентой больше нет: что с
    кадром сделать — в стеклянном меню, которое выпадает из «⋯» (`ActionMenu` кита, деталь 9):
    «Поделиться», «Сохранить на телефон» и красное «Удалить из воспоминания», которого у того, кому
    нельзя, просто нет. Кнопка под открытым меню остаётся подсвеченной (`photo.held`).
    Видео играет 720p-превью
    прогрессивно (`expo-video`, `useVideoPlayer`) прямо по подписанной ссылке и носит свою дорожку с
    таймкодом, звуком и паузой — нативный транспорт выключен.
    Капсула поднимает лист «Сведения о кадре» (`FrameInfoSheet` там же, где остальные листы кадров):
    один запрос `GET /memories/:id/media/:mediaId` на открытие — кто принёс, когда и сколько всего
    кадров у него, файл и размер, размеры в пикселях, камера, место и в каких роликах кадр стоит и на
    какой секунде. Строка, для которой у сервера нет данных, не рисуется вовсе (`frameFacts` в
    `src/frames.ts` — там же и правило, и его тесты); камеру, место и раскладку по роликам пишет
    montage-воркер, так что у старых кадров их нет, и это нормальное состояние листа, а не ошибка.
    Место — только координаты числами: названия нет и не будет, внешний геокодер продукт не берёт.
    Строка ролика ведёт в нынешний плеер воспоминания (`/memory/[id]?montage=…`);
    своего плеера у кадра нет. Имени у ролика пока тоже нет — строка зовёт его «Ролик на 1:00» из
    длительности.
    «Поделиться» отдаёт локальную копию через системный лист (`shareFile` в `src/downloads.ts`), а не
    подписанную ссылку — она умирает через четверть часа. Удаление: своё удаляет каждый, чужое
    только организатор, но решает это `api`, экран лишь рисует строку меню;
    спрашивает он листом подтверждения кита с самим кадром и ценой словами, а не системным `Alert`.
    Забрать что-то домой, отдать наружу или удалить пачкой можно через режим выбора — та самая
    круглая кнопка в шапке. В нём капсула считает выбранное («Выбрано 4» / «38 МБ · 3 фото и
    1 видео», тап — выбрать все или снять), слева вместо «назад» встаёт кнопка лейблов (лист лейблов
    подключает своя веха — пока кнопка выключена), а подвал меняется на «Поделиться · Скачать N
    файлов · Удалить». Удаление спрашивает листом со счётом и удаляет только то, что человеку можно
    (свои кадры; у организатора любые) — решает это всё равно `api`. «Поделиться» пачкой открывает
    системный лист по файлу: ни `Share` из React Native, ни `expo-sharing` больше одного вложения не
    берут. Пустой галерее не нужны ни кнопка выбора, ни фильтр с сортировкой, ни блок роликов: там
    только знак, две строки и «Добавить кадры» (`FramesEmpty`).
    Ссылки живут ~15 минут, а `processing` становится `ready` на стороне воркера, молча. Поэтому
    список перечитывается на фокусе (`useFocusEffect`, как на главной) и, пока в списке есть
    `processing`, ещё раз в три секунды — тихо, без спиннера, и только пока экран впереди. Тихое
    чтение не подменяет уже готовые записи (`keepReady` в `src/frames.ts`): api подписывает ссылки
    заново на каждый ответ, а новый url — это новый файл для `expo-image` и `VideoView`, так что
    иначе всё видимое качалось бы снова каждые три секунды.
    Потягивание вниз осталось для того, кто не хочет ждать.
  - **Ролики** (`src/memory/films.tsx`) — первый блок ленты, а не отдельный экран:
    `GET /memories/:id/montages` полосой, которая листается вбок. Первой в полосе стоит пунктирная
    плитка «Новый ролик» (у организатора; ведёт в `memory/[id]/order`), дальше карточки 232 × 148 —
    готовая открывает плеер в модалке, собирающаяся ведёт на экран ожидания
    (`memory/[id]/montage/[montageId]`), упавшая носит «Повторить». «Сохранить и поделиться» живёт в
    плеере рядом с «Закрыть»: на карточке в полосе места под кнопку нет. Роликов нет — вместо полосы
    пунктирный блок `FilmsEmpty` с двумя кадрами, одной строкой о том, что такое ролик, и бумажной
    «Смонтировать». Список перечитывается тем же приёмом, что и кадры: на фокусе и, пока в нём есть
    `queued` или `processing`, ещё раз в пять секунд — тихо и только пока экран впереди, с той же
    оговоркой про готовые записи (иначе `expo-video` пересобирал плеер на новой ссылке и ролик
    начинался заново каждые пять секунд).
- **`memory/[id]/settings` — Memory settings** (`src/app/memory/[id]/settings.tsx`) — настройки
  воспоминания: карточка события (обложка 68, название, «12–14 сентября · 486 кадров», у
  организатора — круглая «править»), блок «Люди» с «3 из 5 всё скинули» и строками участников,
  отдельный блок «Зрители» (зрителей нет — блока нет) и «Пригласить» внизу. `GET
  /memories/:id/members` отдаёт и статус вклада, и `media_count` — сколько человек принёс именно
  сюда, поэтому галерея ради счёта больше не вычитывается. У зрителя статуса нет вовсе (`null`),
  и меты в его строке тоже. Свой статус — круглая кнопка 44 со значком вклада внутри: нажатие
  гоняет его по кругу «Планирует загрузить» → «Всё загрузил» → «Ждать нечего»; чужие статусы только
  видны. «Править состав» меняет правый знак каждой чужой строки на крестик и спрашивает листом
  подтверждения с ценой в кадрах (у зрителя цены нет — за ним нет кадров); себя-организатора убрать
  нельзя, и кнопки «выйти» здесь нет ни у кого (TASK-113). Карандаша и «Править состав» у
  не-организатора нет вовсе — не выключены, а не нарисованы.
- **`memory/[id]/edit` — Edit the memory** (`src/app/memory/[id]/edit.tsx`) — название, даты и
  обложка за один `PATCH /memories/:id`, и только тем, что тронули (пустое тело api отвергает).
  Экран, а не лист: календарь в лист не влезает. Блок «Когда это было» — общий `EventWhen`
  (`src/memory/when.tsx`). Обложка выбирается листом `CoverSheet` (`src/memory/cover.tsx`) — сетка
  мастера, сначала новые, выбран ровно один кадр — и живёт в слоте до «Сохранить»; «Снять обложку»
  ничего не спрашивает. Уход с несохранёнными правками поднимает мягкий лист подтверждения (без
  красного: ничего не теряется, кроме правок).
- **`memory/[id]/upload` — Upload** (`src/app/memory/[id]/upload.tsx`) — «Ваши кадры»: галерея
  телефона тем же видом, что лента воспоминания (TASK-210). Кадры идут во всю ширину по три в ряд
  (`Tile lane="feed"`, щель `FEED_GAP`), а между днями стоит щель дня-кнопка: тап по дате берёт
  весь день, повторный — снимает. Режим выбора включён с первого мига (круглая кнопка справа в
  шапке, `on=`); выключили — кружки уходят, лента просто листается, а тап открывает кадр во весь
  экран (модалка с `ThemePin value="dark"`: вокруг фотографии ничего светлее её самой). Видео там
  показывает постер и не играет — играет только кадр, уже лежащий в воспоминании.
  Экран носит **две шапки, и выбирает их по тому, есть ли под ними фотографии**: с лентой —
  стеклянная (`GlassBar`, капсула «Ваши кадры» / «в „имя“» **не кнопка**: открывать за ней нечего),
  без ленты — обычная с подзаголовком, как нарисованы `UploadAccess` и `UploadEmpty`. Донный слой
  (`footer="upload"`, 210) стоит, только пока режим выбора включён; «Отправить N файлов»
  недоступна, пока ничего не выбрано, и тогда говорит просто «Отправить».
  Доступ к медиатеке спрашивается кнопкой, а не на входе: до согласия экран не читает ничего, и
  есть состояние «нет доступа» — включая `limited`, когда отдали не всю библиотеку, а несколько
  кадров (тогда «Выбрать все» в дне нет, а счёт в щели нарисован «3 из 61»). Блок отправки и
  застрявшие файлы (`Upload`, `RowStuck` — одна полоса на всю очередь, а не по одной на файл;
  каждый запарковавшийся со своим ✕) стоят шапкой над лентой, а на пустой галерее — над её пустым
  состоянием: очередь видно и тогда, когда брать больше нечего. Кнопка «Send» отдаёт выбранное
  очереди загрузки (ниже) и на этом с ним заканчивает. Недоступный `api` здесь не закрывает экран:
  без него нет только дат мероприятия, а выбирать и ставить в очередь можно и офлайн.
  После отправки — лист «Это всё?» (`SheetAskAll`): «Больше ничего» ставит `done`, «Ещё будет» —
  `more_coming`; закрыли лист, не ответив, — не ставится ничего.
- **`memory/[id]/order` — Order a movie** (`src/app/memory/[id]/order.tsx`) — заказ ролика в четыре
  шага по макету («Ролик: заказ по шагам»): какие кадры взять, о чём ролик, под что монтировать, как
  собрать. Экран, а не лист: четыре шага на лист не ложатся, и «назад» здесь принадлежит шагу, а не
  воспоминанию. Считать умеет `src/montage.ts` — он же и проверяется тестами: состояние мастера,
  отбор кадров и тело заказа (`include_media_ids` / `exclude_media_ids`, история, трек, длина,
  формат). Автоотсев (`screening_rejected` на кадре) здесь — предложение: любой снятый кадр
  возвращается касанием или листом «Что сняли». Материала меньше трёх готовых кадров — вместо шага 1
  поднимается лист «Материала пока мало» и ведёт на `upload`; проверка стоит до шагов, а не после.
  Свой трек уходит в R2 сразу при выборе (`src/music.ts`), чтобы последняя кнопка была одним
  запросом. Полка из пяти слушается прямо на шаге 3: ссылка подписывается на каждое нажатие
  (`GET /music/tracks/:id`), играет ровно один трек, повторное нажатие останавливает, а сам плеер
  принадлежит шагу — уход с него и закрытие мастера и есть тишина. Логика вынесена из экрана в
  `src/music.ts` (`createPreview` / `useTrackPreview`) и проверяется без звука в `montage.test.ts`.
  Заказ — один `POST /memories/:id/montages`, после него экран закрывается, и блок «Ролики»
  перечитывает список на фокусе.
- **`profile` — Profile** (`src/app/profile.tsx`) — экран 8 кита: шапка-строка с именем, ником и
  почтой, обе настройки продукта (тема и язык) со строкой под каждой о том, куда она достаёт, и
  внизу тихий выход из аккаунта — тоже со строкой о последствии, поэтому листом он не спрашивает.
  Две волосяные линии делят экран на «кто вы», «что настроить», «как уйти». Сменить ник или имя
  здесь нельзя (TASK-113): ник берут один раз на `set-username`.
- **`about` — About** (`src/app/about.tsx`) — показывает текущий `EXPO_PUBLIC_API_URL`. Ссылки на
  него в приложении нет: в ките шапка главного экрана держит один значок справа, и это профиль.
  Экран остаётся в навигаторе и открывается маршрутом (`/about`).

Весь HTTP — в `src/api.ts`, состояние сессии — в `src/auth.tsx`.

### Очередь загрузки

Отправка файлов в R2 живёт в `src/uploads.ts` — не в экране: загрузка переживает и уход с экрана, и
перезапуск приложения. По файлу: `POST /memories/:id/media` (ссылки на части, и в этой же заявке —
`file_name`, имя файла на телефоне: другого источника у «сведений о кадре» нет; режется до 255, как
просит `api`), `PUT` кусками прямо в R2 мимо `api`, `POST …/complete` в конце. Что R2 уже принял, помнится по etag'ам частей, поэтому
обрыв догружается, а не начинается заново; протухшая через час ссылка перезапрашивается тем же
`GET …/upload` — тот же `upload_id`, уже залитое остаётся. Очередь лежит в `uploads.json` в
documents (`expo-file-system`) и перечитывается на старте; пустая очередь ничего не делает.

Заводится хук `useUploads()` — один раз в корневом навигаторе (чтобы очередь подхватилась на любом
экране) и ещё раз на экране загрузки, где она показана. Повтор после обрыва — по возвращении в
приложение (`AppState`) и по таймеру раз в 15 секунд, пока в очереди что-то есть. Ссылок нигде не
храним: они живут час, а на возобновлении всё равно запрашиваются заново.

Арифметика частей (что нарезать, что уже принято, сколько процентов) — в `src/upload-queue.ts`,
отдельным чистым модулем: это и есть докачка, и она проверяется тестом без телефона.

Причина, по которой файл встал, в очереди хранится строкой-причиной (`UploadFailure` там же), а не
готовым текстом: очередь лежит на диске и переживает и смену языка, и перезапуск. Текст собирает
`failureText(s, …)` в момент отрисовки баннера. Готовых фраз в очередь не кладём — иначе они
застревают в языке, в котором были написаны. Перечитанные со старта причины сбрасываются: они
относятся к прошлому запуску, и повтор скажет, что не так сейчас.

Обратная дорога — `src/downloads.ts`: разрешение медиатеки, скачивание в кэш, сохранение в
галерею телефона и уборка кэша за собой. Ею пользуются оба экрана, которые что-то кладут на
телефон, — галерея (оригиналы) и экран монтажа (готовый ролик).

### Журнал монтажа

Рассказ режиссёра о том, как собирается ролик, живёт в `src/montage-journal.ts` — отдельно от
экранов, как и арифметика заказа: всё чтение и все выводы проверяются без телефона
(`montage-journal.test.ts`, ответы записаны по форме из README api).

Читается одним хуком — `useMontageJournal(token, memoryId, montageId, { stage, media_id })`. Пока
ролик в очереди или в работе, он опрашивает `GET …/journal` раз в 1.5 секунды; курсор — наибольший
`id` отданной порции, и при `has_more` следующая порция запрашивается сразу, в том же опросе, а не
через полторы секунды: между двумя опросами может лечь больше записей, чем влезает в порцию, и
«самые свежие» оставили бы в середине дыру. Готовый или упавший ролик не опрашивается вовсе, экран
не в фокусе или приложение в фоне — опрос стоит и возобновляется чтением при возвращении. Обрыв
связи ничего не стирает: прочитанное остаётся, а `standing` становится `offline` до первого
удавшегося опроса. Назад по журналу — `loadOlder()`, по одной порции на зов.

Всё, что экран берёт из ответа, посчитано там же: какой этап идёт (`currentStage`, `stageNumber`),
что в руках у режиссёра (`inHand`), две последние записи этапа (`lastOfStage`), «осталось ≈ N мин»
(`minutesLeft`), рамка «куда смотрит» в точках карточки (`gazeAt` — доли 0..1 превращаются в левый
верхний угол квадрата 96 у `CardNow`), и пилюли решения словами (`marksOf`, `reasonWord`). Печать
мысли — `useTypedThought(text, fresh)`: допечатывается только запись, пришедшая при открытом экране
(`isFresh`), при «уменьшить движение» фраза появляется целиком. Слова этапов, решений и причин — в
`s.montage.stage` и `s.montage.live`.

### Как добавить экран за входом

Гейт — `Stack.Protected` в `src/app/_layout.tsx`; ключ к нему — `status` из `useAuth()`. Экраны
не прячутся, а **не существуют**: `expo-router` выкидывает из навигатора всё, что гейт не пустил.

| `status`         | Какие экраны существуют                                            |
|------------------|--------------------------------------------------------------------|
| `loading`        | `login`, `login/email`, `login/code` — под сплэшем, чтобы холодному старту было где стоять |
| `signed-out`     | `login`, `login/email`, `login/code`                               |
| `needs-username` | `consent`, `set-username` — в этом порядке: соглашение стоит перед ником, и первый объявленный экран и есть тот, на который гейт приземляет |
| `ready`          | `index`, `create`, `profile`, `about`                              |

Новому экрану за входом нужны **две** вещи: файл в `src/app/` и строка в блоке `status === 'ready'`.

```tsx
<Stack.Protected guard={status === 'ready'}>
  <Stack.Screen name="memories" options={{ title: 'Memories' }} />
</Stack.Protected>
```

Забыли вторую — маршрута **молча** не будет: переход по нему не упадёт с ошибкой, а уведёт на
первый экран, который всё-таки объявлен.

Текущий пользователь — `const { user, token } = useAuth()`; за гейтом он уже загружен, и `token`
не `null`. Вызов API — новая функция в `src/api.ts`, которая принимает `token` параметром;
заголовок `Authorization: Bearer` вешает сам `request`:

```ts
export function listMemories(token: string): Promise<Memory[]> {
  return request('/memories', { token });
}
```

Ошибку с такого вызова показывают через `errorMessage(error)` — она достаёт формулировку самого
API. Ветвиться на конкретный ответ (`401`, `409`) можно по `error instanceof ApiError` и
`error.status`.

## Чего здесь нет

CI, профили EAS кроме `development` (пилотная раздача и прод придут со своей задачей),
стейт-менеджер — всё это принесёт та фича, которой понадобится. Экраны на пилоте проверяются
руками: vitest здесь под чистую логику вроде `src/media-window.ts` и под истории деталей.
Второе держится на одном алиасе в `vitest.config.mjs` — `react-native` в тестах подменяется на
`react-native-web`, — и отвечает только за разметку: сколько кадров нарисовала карточка и что она
показывает, когда их нет. Что нативный `Image` делает с подписанной ссылкой, из node не видно.

Нет и веб-сборки как мишени для проверок. `npm run web` (`expo start --web`) из `package.json` не
убран и запускается, но проверять продукт в браузере нечестно: единственный клиент — телефон, iOS и
Android, и под паритет с ним веб не чинится. Проверяйте на симуляторе, эмуляторе, в Expo Go или
dev-билде — как описано в «Запуске» выше.

В браузере отваливаются ровно две вещи, которых на устройстве нет:

- **Вход не сохраняется.** `src/auth.tsx` кладёт токен в `expo-secure-store`
  (`SecureStore.setItemAsync`/`getItemAsync`, ключ `session-token`), а на web это пустая заглушка —
  сессии просто негде остаться.
- **Запросы к API не уходят.** Сервер не отдаёт браузеру заголовков доступа (CORS) — он их и не
  должен, клиентов-браузеров у продукта нет.

Оба выглядят как блокеры продукта и оба уже стоили времени на поиск несуществующего бага. Алиас
`react-native-web` выше к этому отношения не имеет: он живёт только в vitest под node.
