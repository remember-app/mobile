# Remember — мобильное приложение

Expo / React Native (TypeScript), iOS + Android. Единственный клиент продукта; общается только с
`api`. Общий пакет типов с `api` не заводится — нужные типы дублируются здесь (`src/api.ts`).

Сейчас здесь клиент аккаунтов (m-3): вход тремя способами, токен сессии в `expo-secure-store`
(Keychain на iOS, EncryptedSharedPreferences на Android), ник, профиль, выход — и гейт, который
решает, какие экраны вообще существуют. Поверх него — воспоминания: список своих на главной,
создание нового и само воспоминание одним экраном с тремя лицами (кадры, ролики, люди), плюс выбор
кадров на телефоне. Все они собраны по разделу «Экраны» кита — что где стоит, см. ниже.

Из трёх входов вживую работает только ссылка на email. Apple и Google подключены целиком, но им
нужны ключи на стороне `api` — без них он отвечает `501` — и **dev-билд**: в Expo Go нет ни
entitlement на Sign in with Apple, ни нашей URL-схемы. Кнопке Google нужен вдобавок
`EXPO_PUBLIC_GOOGLE_CLIENT_ID`.

Экран входа показывает только те входы, которыми в этой сборке можно пройти: кнопки Apple нет там,
где `AppleAuthentication.isAvailableAsync()` отвечает `false`, кнопки Google — там, где не задан
`EXPO_PUBLIC_GOOGLE_CLIENT_ID`. Ссылка на почту стоит всегда и, оставшись одна, берёт себе ember
экрана. Отказ `501` от сервера при этом обрабатывается по-прежнему: сигнал на телефоне может
устареть, и тогда отвечать приходится словами.

## Требования

- Node 20+
- Expo Go на телефоне **или** iOS-симулятор / Android-эмулятор
- Запущенный `api` (соседний репозиторий) — без него не войти, а главный экран вместо списка
  покажет ошибку и кнопку «Try again»

## Запуск

```sh
npm install
EXPO_PUBLIC_API_URL=http://localhost:3000 npx expo start
```

Дальше — `i` (iOS-симулятор), `a` (Android-эмулятор) или QR-код в Expo Go.

Чтобы не писать переменную каждый раз, положите её в `.env` (файл в `.gitignore`):

```sh
EXPO_PUBLIC_API_URL=http://localhost:3000
```

### `EXPO_PUBLIC_API_URL`

Базовый URL API. Без неё берётся `http://localhost:3000`.

`localhost` работает только на симуляторе/эмуляторе. **С телефона через Expo Go** подставьте
IP машины в локальной сети, например `EXPO_PUBLIC_API_URL=http://192.168.1.10:3000`.

Переменная подставляется в бандл на сборке — после её изменения перезапустите `expo start`.
По той же причине в `EXPO_PUBLIC_*` не кладутся секреты: содержимое уезжает в собранное приложение.

### Ссылка входа по email в разработке

Когда на API явно включён `EMAIL_LOGIN_DEV_BYPASS` (значение `1` или `true`), адрес — на домене
`test.test`, а сам API не в проде, `POST /auth/email/start` отдаёт ссылку
`remember://auth/email?token=…` прямо в ответе вместо письма. Экран входа сам достаёт из неё
токен и меняет на сессию, держа при этом плашку «вход для разработки»: руками делать нечего —
адрес, кнопка, вы внутри.

Нужны все три условия сразу. Ключи почты (`RESEND_API_KEY`, `MAIL_FROM`) на обход больше не
влияют: с любым другим адресом уходит настоящее письмо, а без ключей приходит 503.

В лог ссылка не пишется, это ключ от аккаунта. Если она нужна отдельно — например, чтобы открыть
сам экран `auth/email`, — возьмите её из ответа:

```sh
curl -s localhost:3000/auth/email/start \
  -H 'content-type: application/json' -d '{"email":"you@test.test"}'
```

**Схема `remember://` работает только в dev-билде.** В Expo Go она принадлежит не нам, и
`xcrun simctl openurl booted "remember://…"` падает с `LSApplicationWorkspaceErrorDomain 115`.
В Expo Go тот же экран открывается через схему Expo:

```sh
xcrun simctl openurl booted "exp://127.0.0.1:8081/--/auth/email?token=<TOKEN>"
```

## Пуши

Код целиком в `src/push.ts` (хук `usePush()` в корневом навигаторе): после входа спрашивается
разрешение, токен уходит в `POST /me/push-tokens`, тап по пушу «вас позвали» открывает
`/memory/[id]/upload` того воспоминания. Пуш «ролик готов» несёт, кроме `memoryId`, ещё и
`montageId` — по нему открывается `/memory/[id]?face=films`, то есть само воспоминание на лице
«Ролики», где они и лежат: досылать туда нечего.
Не получилось — в логе Metro строка
`push registration skipped: …` (нет `projectId`, отказ в разрешении, симулятор); экрана про это
нет и не будет: пуш — не единственный способ узнать о приглашении.

**В Expo Go удалённых пушей нет** (с SDK 53), нужен dev-билд — поэтому в зависимостях
`expo-dev-client`, а в `eas.json` профиль `development`.

Чтобы это заработало вживую, нужен Expo-аккаунт — **этого шага здесь нет, и в коде ничего не
зашито**:

1. `npx eas init` в этой папке — он и запишет `expo.extra.eas.projectId` (и `owner`) в `app.json`.
   Именно это поле читает `getExpoPushTokenAsync`; без него в логе `No "projectId" found`.
2. `ios.bundleIdentifier` и `android.package` в `app.json` — их спросит первая `eas build` и
   запишет сама.
3. `npx eas build --profile development -p ios` (или `android`), поставить сборку на телефон,
   `npx expo start --dev-client`. Переменные (`EXPO_PUBLIC_API_URL`) dev-билд берёт с дев-сервера,
   то есть из локального `.env`, а не из сборки.
4. Ключи APNs / FCM — `npx eas credentials`.

Плагин `expo-notifications` ставит `aps-environment: development`; для TestFlight и прода ему
понадобится `mode: 'production'`.

## Оболочка и токены

Дизайн-правда продукта — `design/kit.html` в корневом репозитории (одна комната при двух светах:
«Тёмная комната» и «Контактный лист»), её единственный перенос сюда — `src/theme.ts`: цвета, ритм,
радиусы, длительности и шесть ролей типографики, имена и значения один в один с китом. Свои цвета и
отступы экраны не заводят — берут отсюда.

- Заголовки — **Bricolage Grotesque** (`@expo-google-fonts/bricolage-grotesque`), `type.display`
  и `type.title`; всё остальное системным шрифтом. Шрифт грузится в `_layout.tsx` и держит сплэш
  вместе с проверкой сессии.
- Значки — **Lucide** (`lucide-react-native`), один набор на весь продукт, обводка `1.75`. Он
  тянет за собой нативный `react-native-svg`: в Expo Go он есть, а **старый dev-билд надо
  пересобрать**.
- Кадры рисует **`expo-image`** (внутри `src/kit/tile.tsx`, наружу не торчит): родной `Image` не
  умеет `ph://…` — ссылку, которой iOS называет снимок в медиатеке, — и падает на ней красным
  экраном «No suitable image URL loader». `expo-image` спрашивает Photos напрямую, для видео
  отдаёт постер, и отдаёт уже уменьшенным под плитку. Модуль нативный: **старый dev-билд надо
  пересобрать**. Его манифест доливает в андроидную сборку `ACCESS_NETWORK_STATE` — разрешение
  обычного уровня, без диалога, но в списке на Play оно появится. Проявляется кадр **его же**
  `transition`, а не `Animated` поверх: нативный драйвер пишет прямо во вью, к которому привязан, а
  здесь это чужой класс вокруг нативного — значение доезжало до единицы в JS, картинка оставалась
  на нуле и появлялась только от постороннего перерендера. Плитки на экране выбора из-за этого были
  пустыми, пока по ним не ткнёшь.
- Родного хедера нет нигде (`headerShown: false`), фон навигатора — `ink` через `ThemeProvider`,
  так что шапку экран рисует сам.
- Приложение идёт за темой телефона, поэтому `userInterfaceStyle: "automatic"` в `app.json`: при
  `"dark"` система вообще не сказала бы, что телефон в светлом режиме, и светлая тема не включилась
  бы никогда. Настройка нативная — **ещё одна причина пересобрать dev-билд**.
- Продукт вертикальный, но нативного замка на это больше нет: в `app.json` стоит
  `orientation: "default"`, а портрет держит `src/orientation.ts` — `lockPortrait()` из
  `_layout.tsx` при запуске и снятие замка на время двух просмотров во весь экран, кадра и ролика
  (`useTurnsWithPhone`, лица `frames.tsx` и `films.tsx`). Стоявший там `"portrait"` компилировался
  в Info.plist и андроидный манифест и был выше любого JS: `supportedOrientations` у обоих Modal
  не делал ничего, и открытый кадр не поворачивался вместе с телефоном (TASK-124). Замок ставит
  нативный `expo-screen-orientation`, и сама смена в `app.json` тоже нативная — **старый dev-билд
  надо пересобрать**.

### Тема — светлая и тёмная

Тем ровно две (`backlog/docs/doc-9`), и различает их только цвет: ритм, отступы, радиусы, шрифты и
длительности общие и о теме не знают. В `src/theme.ts` лежат оба набора кита один в один, в
`src/kit/shades.ts` — второй ярус цвета (что читается на ember, rust и fixed и чем они подкрашивают
поверхность), тоже парой наборов.

- **Какая тема сейчас** — `src/theme.ts`: берётся от телефона (`Appearance` из React Native,
  нативного модуля для этого не нужно), меняется вместе с ним на ходу. `setTheme('dark' | 'light')`
  переопределяет систему, выбор лежит в `expo-secure-store` и переживает перезапуск. Устроено ровно
  как язык — модульная переменная и `useSyncExternalStore`, а не контекст.
- **Компонент рисует по актуальной теме**: свои стили он получает не импортом набора, а хуком —
  `const useStyles = themed(({ color }) => StyleSheet.create({ … }))`, дальше `useStyles()` в теле.
  Каждая тема собирается один раз и запоминается. Цвет, который нужен не в стиле, а в пропсе, —
  `useTheme()`.
- Экраны `src/app/*` пока читают фиксированный тёмный набор (`color`, `shade.lineHover`,
  `focusRing`); их переводит отдельная задача, и вместе с ней эти экспорты уходят.
- Кадры и медиа не перекрашиваются ни в одной теме, а затемнение на кадре (`scrim` и `onScrim`)
  общее: оно лежит на фотографии, а не на интерфейсе.

### Компоненты кита

`src/kit/` — компоненты кита (секции 2–15) на React Native: кнопки, поля, шапка и нижняя полоса
действия, чипы и участники, карточка воспоминания, плитка кадра, загрузка, карточка ролика, полосы
сообщений, лист подтверждения, пусто и ожидание, переключатель из двух-трёх (`Segment`, у него
`hint` — строка под рядом о том, куда настройка достаёт, и `wide` — ряд во всю ширину колонки;
`wide` берут там, где значений два, на трёх длинное слово режется). Строка-подсказка сама по себе —
`Hint`, ею подписаны и поля, и выход из аккаунта. Единственное место, откуда экраны берут внешний
вид; импорт — из корня папки:

```tsx
import { AppBar, Button, CardMemory, Text } from '@/kit';
```

Имена компонентов и пропсов повторяют классы кита (`CardMemory` — `.card-memory`, `sm` — `.btn-sm`,
`tone="error"` — `.banner-error`), чтобы экран сверялся с китом построчно. Значения берутся из
`theme.ts`, второй ярус цвета — из `src/kit/shades.ts` через тему; своих цветов компоненты не
заводят и жёстко тёмными не бывают.

Три вещи, о которые спотыкается тот, кто их подключает:

- **Ни одного зашитого слова.** Всё видимое приходит пропсом: кит — это внешность, слова у экранов.
- **Текст — только `Text` из кита.** В CSS цвет наследуется от `body`, в RN — ни от чего, поэтому
  родной `Text` с одним лишь `type.body` даёт чёрное по угольному. Роль просите словом:
  `<Text role="title">`.
- **Движение гаснет по системной настройке.** Вращение, проявление кадра, подъём листа и сдвиг
  нажатия слушают «уменьшить движение»; она спрашивается один раз на всё приложение в
  `src/kit/interaction.ts`. Оттуда же `hitSlop()` — им добирают до 44×44 всё, что нарисовано меньше.

Своего тумблера у кита нет — на выбор из значений он отвечает `Segment`. Но там, где вещь просто
включена или выключена, стоит платформенный `Switch` в цветах кита, и стоит он один раз:
`Toggle` (`src/kit/toggle.tsx`). Раньше те же четыре цветовых пропса были выписаны на двух экранах,
и один из них (`activeThumbColor`, см. `src/switch.d.ts`) — из тех, чьё отсутствие никто не
замечает. Обе копии сняты, `<Switch>` вживую стоит только внутри `Toggle`.

Лист снизу — это `Sheet` (`src/kit/sheet.tsx`): подложка, ручка, подъём, закрытие по тапу вне,
и `children` сверху. На нём стоит `ConfirmSheet`, которым спрашивается необратимое вместо
системного `Alert.alert`, — и на нём же экран собирает свою форму, когда её незачем держать
открытой (приглашение на `memory/[id]`). Экраны переведены на кит все, каждый своей задачей
вехи m-7.

## Язык

Языка два — русский и английский, третьего не будет (`backlog/docs/doc-8`). Оба набора написаны
руками: английский не перевод русского, русский не перевод английского.

- **Слова** — `src/strings.ts`: один ключ, два набора. Форму задаёт `en`, `ru` обязан её заполнить,
  поэтому ключ с одним набором роняет `npm run typecheck`, а не показывает английское слово посреди
  русского экрана. Русские числительные считаются в трёх формах (`1 кадр`, `2 кадра`, `5 кадров`)
  своей функцией: `Intl.PluralRules` есть в Hermes не везде.
- **Язык** — `src/language.ts`: берётся от телефона (`expo-localization`), незнакомый язык телефона
  даёт английский. Переключается `setLanguage('ru' | 'en')`, выбор лежит в `expo-secure-store`
  (не секрет — просто хранилище, которое в приложении уже есть) и переживает перезапуск.
  Значение одно на всё приложение, поэтому это модульная переменная, а не контекст: `currentLanguage()`
  спрашивают из любой функции, компоненты берут `useLanguage()` / `useStrings()` и сами
  перерисовываются на переключении. Никакого i18n-фреймворка под этим нет — словарь и резолвер, как
  `theme.ts` для дизайна.
- **Даты** идут по языку приложения, а не по системной локали телефона: название месяца в
  `src/dates.ts` спрашивается у `currentLanguage()`. Раньше там стоял `undefined`, а это для
  форматтера значит «локаль устройства» — из-за него на телефоне с русской локалью посреди
  английских подписей стояло русское число.

`expo-localization` — нативный модуль: в Expo Go он есть, **старый dev-билд надо пересобрать**.
Поэтому же любой тест, который тянет `@/dates`, `@/language`, `@/theme` или любой компонент кита,
подменяет `expo-localization` и `expo-secure-store` через `vi.mock` — в node их импорт падает на
`__DEV__`.

Экраны словарь ещё не читают (это отдельная задача вехи m-13), в `strings.ts` пока то, что
приложение говорит вне экранов: ошибки, состояния и слова, которые повторяются везде.

## Экраны

Навигация — `expo-router` (файловая маршрутизация, `src/app/`), корневой layout — `Stack` с гейтом.

У воспоминания **два** экрана: само оно и выбор кадров на телефоне. Само воспоминание — один экран
с тремя лицами (кит, «Экраны» 4–6): «не три экрана с одним именем, а один экран с тремя лицами —
имя стоит в шапке, лицо выбирают переключателем под ней». Лица — «Кадры», «Ролики», «Люди»; до
TASK-101 это были три маршрута с тремя подписями в шапке и безымянной иконкой между ними.

Всё в `src/app/` — маршрут, поэтому сами лица лежат рядом, в `src/memory/`: `frames.tsx`,
`films.tsx`, `people.tsx` и общая шапка `head.tsx`. Маршрут (`src/app/memory/[id].tsx`) держит
только то, что у трёх лиц общее: какое лицо открыто и само воспоминание (имя, даты, роль) — оно
читается один раз на все три, чтобы имя в шапке не мигало при переключении. Свой список каждое лицо
читает само, когда его включают. Лицо можно попросить ссылкой — `/memory/[id]?face=films`; без
просьбы открываются «Кадры».

- **`login` — Sign in** (`src/app/login.tsx`) — до трёх входов: письмо со ссылкой, Apple и Google;
  недоступный провайдер не рисуется вовсе, а не стоит выключенным.
- **`auth/email` — Signing in** (`src/app/auth/email.tsx`) — куда приземляется ссылка
  `remember://auth/email?token=…`: меняет токен из ссылки на сессию, протухшую отправляет за новой.
- **`set-username` — Pick a username** (`src/app/set-username.tsx`) — единственный экран, доступный
  вошедшему аккаунту без ника; занял ник — открылось остальное.
- **`index` — Remember** (`src/app/index.tsx`) — главный экран: список воспоминаний, где аккаунт
  организатор или участник (`GET /memories`), с состояниями «загрузка», «пусто» и «ошибка +
  Try again». Перезапрашивается на каждый фокус, поэтому возврат с `create` показывает новое
  воспоминание сам. Карточка открывает воспоминание на «Кадрах».
- **`create` — New memory** (`src/app/create.tsx`) — название и дата (или интервал) мероприятия;
  дату выбирает системный календарь `@react-native-community/datetimepicker`, так что ввести
  неверную нельзя. Уходит в `POST /memories` началом и концом **local** суток — `toISOString()`
  даёт RFC 3339 со смещением, которого требует `api`.
- **`memory/[id]` — Memory** (`src/app/memory/[id].tsx`) — само воспоминание, три лица под одной
  шапкой. Слева в шапке «назад» (без стека — `replace` на список), справа не больше одного значка,
  и только на «Кадрах»; под шапкой — `Segment wide` кита с тремя словами.
  - **Кадры** (`src/memory/frames.tsx`) — что сложили участники (`GET /memories/:id/media`): сетка
    деривативов от края до края, которую видит любой участник, включая `viewer`. Оригиналы отсюда
    не тянутся вообще. Медиа, которому воркер ещё (или уже никогда) не сделал превью, — плитка с
    подписью вместо картинки. Тап открывает крупно, видео играет 720p-превью прогрессивно
    (`expo-video`, `useVideoPlayer`) прямо по подписанной ссылке. Там же «Delete» — своё удаляет
    каждый, чужое только организатор, но решает это `api`, экран лишь рисует кнопку; спрашивает он
    листом подтверждения кита, а не системным `Alert`. «Скачать всю галерею» — тот самый значок в
    шапке, подвал — одна кнопка «Добавить ещё» (её нет у тех, кто может только смотреть).
    Ссылки живут ~15 минут, а `processing` становится `ready` на стороне воркера, молча. Поэтому
    список перечитывается на фокусе (`useFocusEffect`, как на главной) и, пока в списке есть
    `processing`, ещё раз в три секунды — тихо, без спиннера, и только пока экран впереди.
    Потягивание вниз осталось для того, кто не хочет ждать.
  - **Ролики** (`src/memory/films.tsx`) — `GET /memories/:id/montages`: список карточек, заказ у
    организатора (длина и трек — лист снизу), повтор упавшей сборки, просмотр в модалке и «Save and
    share».
  - **Люди** (`src/memory/people.tsx`) — `GET /memories/:id/members` с ролью и статусом вклада у
    каждого, приглашение по нику и ссылкой (лист снизу), исключение участника организатором. Строка
    человека в две линии: сверху имя, роль и крестик, снизу — ник, статус и сколько кадров он уже
    принёс. Счёта на участнике у API нет, поэтому он считается по `GET /memories/:id/media` — второе
    чтение рядом с ростером, и его отказ оставляет прочерк вместо числа, а список людей не роняет.
    В своей строке на месте статуса стоит чип «Мне нечего добавлять» (пока статус не `done` и не
    `nothing`) — им же он и ставится. Сюда же приводит принятое приглашение (`?face=people`).
- **`memory/[id]/upload` — Upload** (`src/app/memory/[id]/upload.tsx`) — выбор фото и видео из
  галереи телефона. Доступ к медиатеке спрашивается кнопкой, а не на входе: до согласия экран не
  читает ничего, и есть состояние «нет доступа» — включая `limited`, когда отдали не всю
  библиотеку, а несколько кадров. Кнопка «Select all from that date» — это `assetsInEventWindow`
  из `src/media-window.ts` по окну мероприятия, и ничего больше. Кнопка «Send» отдаёт выбранное
  очереди загрузки (ниже) и на этом с ним заканчивает. Экран одет в кит: сетка — контактный лист
  из `Tile` (выбранный кадр в рамке ember с меткой в углу, у видео — длительность), сообщения и
  отказ в доступе — `Banner`, отправка внизу — одна полоса `Upload` на всю очередь, а не по одной
  на файл; запарковавшиеся названы поимённо, каждый со своим ✕. Недоступный `api` здесь не
  закрывает экран: без него нет только дат мероприятия и автоподбора, а выбирать и ставить в
  очередь можно и офлайн.
- **`profile` — Profile** (`src/app/profile.tsx`) — экран 8 кита: шапка-строка с именем, ником и
  почтой, обе настройки продукта (тема и язык) со строкой под каждой о том, куда она достаёт, и
  внизу тихий выход из аккаунта — тоже со строкой о последствии, поэтому листом он не спрашивает.
  Две волосяные линии делят экран на «кто вы», «что настроить», «как уйти». Сменить ник или имя
  здесь нельзя (TASK-113): ник берут один раз на `set-username`.
- **`about` — About** (`src/app/about.tsx`) — показывает текущий `EXPO_PUBLIC_API_URL`. Ссылки на
  него в приложении нет: в ките шапка главного экрана держит один значок справа, и это профиль.
  Экран остаётся в навигаторе и открывается маршрутом (`/about`).

Весь HTTP — в `src/api.ts`, состояние сессии — в `src/auth.tsx`.

### Очередь загрузки

Отправка файлов в R2 живёт в `src/uploads.ts` — не в экране: загрузка переживает и уход с экрана, и
перезапуск приложения. По файлу: `POST /memories/:id/media` (ссылки на части), `PUT` кусками прямо
в R2 мимо `api`, `POST …/complete` в конце. Что R2 уже принял, помнится по etag'ам частей, поэтому
обрыв догружается, а не начинается заново; протухшая через час ссылка перезапрашивается тем же
`GET …/upload` — тот же `upload_id`, уже залитое остаётся. Очередь лежит в `uploads.json` в
documents (`expo-file-system`) и перечитывается на старте; пустая очередь ничего не делает.

Заводится хук `useUploads()` — один раз в корневом навигаторе (чтобы очередь подхватилась на любом
экране) и ещё раз на экране загрузки, где она показана. Повтор после обрыва — по возвращении в
приложение (`AppState`) и по таймеру раз в 15 секунд, пока в очереди что-то есть. Ссылок нигде не
храним: они живут час, а на возобновлении всё равно запрашиваются заново.

Арифметика частей (что нарезать, что уже принято, сколько процентов) — в `src/upload-queue.ts`,
отдельным чистым модулем: это и есть докачка, и она проверяется тестом без телефона.

Обратная дорога — `src/downloads.ts`: разрешение медиатеки, скачивание в кэш, сохранение в
галерею телефона и уборка кэша за собой. Ею пользуются оба экрана, которые что-то кладут на
телефон, — галерея (оригиналы) и экран монтажа (готовый ролик).

### Как добавить экран за входом

Гейт — `Stack.Protected` в `src/app/_layout.tsx`; ключ к нему — `status` из `useAuth()`. Экраны
не прячутся, а **не существуют**: `expo-router` выкидывает из навигатора всё, что гейт не пустил.

| `status`         | Какие экраны существуют                                            |
|------------------|--------------------------------------------------------------------|
| `loading`        | `login`, `auth/email` — под сплэшем, чтобы холодному старту по ссылке было куда приземлиться |
| `signed-out`     | `login`, `auth/email`                                              |
| `needs-username` | `set-username`                                                     |
| `ready`          | `index`, `create`, `profile`, `about`                              |

Новому экрану за входом нужны **две** вещи: файл в `src/app/` и строка в блоке `status === 'ready'`.

```tsx
<Stack.Protected guard={status === 'ready'}>
  <Stack.Screen name="memories" options={{ title: 'Memories' }} />
</Stack.Protected>
```

Забыли вторую — маршрута **молча** не будет: переход по нему не упадёт с ошибкой, а уведёт на
первый экран, который всё-таки объявлен.

Текущий пользователь — `const { user, token } = useAuth()`; за гейтом он уже загружен, и `token`
не `null`. Вызов API — новая функция в `src/api.ts`, которая принимает `token` параметром;
заголовок `Authorization: Bearer` вешает сам `request`:

```ts
export function listMemories(token: string): Promise<Memory[]> {
  return request('/memories', { token });
}
```

Ошибку с такого вызова показывают через `errorMessage(error)` — она достаёт формулировку самого
API. Ветвиться на конкретный ответ (`401`, `409`) можно по `error instanceof ApiError` и
`error.status`.

## Чего здесь нет

CI, профили EAS кроме `development` (пилотная раздача и прод придут со своей задачей),
стейт-менеджер — всё это принесёт та фича, которой понадобится. Экраны на пилоте проверяются
руками: vitest здесь под чистую логику вроде `src/media-window.ts` и под структуру компонента кита.
Второе держится на одном алиасе в `vitest.config.mjs` — `react-native` в тестах подменяется на
`react-native-web`, — и отвечает только за разметку: сколько кадров нарисовала карточка и что она
показывает, когда их нет. Что нативный `Image` делает с подписанной ссылкой, из node не видно.
